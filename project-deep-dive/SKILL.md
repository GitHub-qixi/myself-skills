# 项目深度学习

输入示例：深度学习某项目。

## 选出值得深学的部分

1. 从项目的真实入口、公开 API 或代表性用例追踪核心场景。找出实现核心价值的代码、关键设计约束和影响结果的故障边界。结合实现、配置和测试确认实际启用范围。只有文档或描述时，按材料能支持的范围分析，并标明依据。
2. 按对理解项目的贡献排序。优先选择决定核心行为、解释关键设计取舍或影响典型改动的部分。用具体问题命名，例如“流式响应中断时如何释放上游连接”。常规支撑模块只在对理解核心链路有帮助时列入，数量随项目调整。
3. 每项附可复查的代码、测试或文档入口。项目类型、依赖名和示例只作为搜索线索。只有追到项目自身可达的行为选择、调度或推进逻辑，才列 Agent 编排。透传工具调用字段、依赖 Agent SDK 或调用上游 Agent 均不足以证明本项目有编排。其他能力同样按实际职责取证。
4. 为每项选择足够支撑用户目标的掌握等级。未指定目标时，以能解释核心设计并独立完成常见改动或排障为基准。未核实的实现不列为必学项。若证据缺口会影响重点判断，在清单后简述缺口和核查入口。

## 掌握等级

- **L1 识别**：能找到入口并说清职责与边界。
- **L2 解释**：能追踪主要调用链或数据流，解释关键设计理由。
- **L3 修改与排查**：能独立完成一项典型改动或定位一类故障，并验证结果。
- **L4 重构与扩展**：能在保留关键行为和约束的前提下，重构、扩展或重新实现该机制。

核心部分通常选 L3，理解链路所需的支撑部分通常选 L2。仅需知道边界时选 L1，用户目标涉及重构、扩展或重实现时才将相关部分定为 L4。用该项目的具体任务和可观察结果描述达标表现。

## 输出

用简体中文，按 [清单模板](references/output-template.md) 直接给出重点及目标掌握程度。默认输出一张表，证据和达标表现放在对应行。
