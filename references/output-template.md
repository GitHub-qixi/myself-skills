# 项目深度透视输出模板

当用户说"我想吃透某个项目"时，按下面模板回答。

---

## 1. 项目定位

这个项目属于哪一类，主要解决什么问题，它的核心价值在哪里。

## 2. 核心功能

列出项目的主要功能模块，例如：

- 请求入口
- 路由分发
- 渠道/模型适配
- 上下文与记忆管理
- Agent 编排
- 工具调用
- 计费与额度
- 日志与监控
- 权限与鉴权
- 部署与配置

（按项目类型裁剪，不是每个项目都有全部模块）

## 3. 必须吃透的关键点

例如（网关类项目）：

- 请求从进入项目到返回响应的完整链路
- 上下文如何保存、截断、压缩和恢复
- Agent 编排如何决定下一步动作
- 工具调用如何注册、触发和返回结果
- 渠道适配如何统一不同模型的输入输出
- 计费、额度、限流如何保证一致性
- 错误、超时、重试、降级如何处理
- 配置、环境变量、密钥如何管理
- 数据模型如何支撑核心业务
- 日志如何用于排查问题

## 4. 每个点的掌握标准

每个点都要回答三个问题：

- 能不能用自己的话讲清楚它的作用？
- 能不能画出它的数据流或调用链？
- 能不能改动它、排查它或替换它？

掌握程度分为：

- L1 了解：知道它是什么
- L2 理解：知道它为什么存在
- L3 掌握：能独立修改和排查
- L4 吃透：能重构、扩展或重新实现

## 5. 学习路径

建议按这个顺序学习：

1. 先看入口和主流程
2. 再看请求/数据流转
3. 然后看核心状态管理
4. 再看外部依赖和适配层
5. 最后看运维、监控、部署和扩展

## 6. 验证方式

学完后可以做这些验证：

- 画出完整架构图
- 画出请求时序图
- 复现一个核心功能
- 修改一个配置或模块
- 排查一个模拟错误
- 写一份自己的项目拆解文档

# 完整示例：输入"我想吃透 new-api 项目"

## 项目定位

这是一个大模型 API 网关 / 代理类项目，主要用来统一管理多个模型渠道，处理请求路由、上下文、计费、日志和权限。

## 必须吃透的点

- 请求入口和路由分发
- 渠道/模型适配层
- 上下文与对话历史管理
- Agent 编排与工作流
- 工具调用机制
- Token 计算与计费逻辑
- 鉴权与权限控制
- 限流、重试、降级策略
- 日志、监控和审计
- 配置、部署和密钥管理

## 掌握标准

- 能画出"用户请求 → 网关 → 渠道 → 模型 → 返回"的完整链路
- 能说明上下文如何被保存、截断或压缩
- 能解释 Agent 如何决定下一步调用哪个工具
- 能说明计费如何避免多扣、漏扣
- 能新增一个模型渠道或修改一个路由规则
- 能通过日志定位一次失败请求
