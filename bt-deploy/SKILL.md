# 宝塔部署上线

## 输入与范围

- 管理入口为宝塔完整 URL，首次登录使用用户提供的账号和密码。已有登录会话可以直接复用。入口包含安全路径时保留原样。
- 从当前对话和工作区确认项目目录或仓库、发布版本、目标域名、数据库来源与迁移范围、交付位置。优先检查项目已有配置，只询问无法推断且阻塞工作的输入。
- 分开处理宝塔面板连接的 TLS 与业务站点的 HTTPS。确认目标站点的证书需求，既有站点、共享服务和面板全局设置按各自授权处理。
- 凭据只用于指定面板登录。部署包与上线文档排除口令、令牌、私钥及其他不需要传输的本地配置。数据库快照仅上传到授权服务器的非公开目录。

## 执行顺序

1. 先用提供的入口和账号尝试正常连接。登录页可达就走标准登录流程。遇到 404、证书、代理或浏览器接管问题，按 [连接与回退](references/connection.md) 排查。直接方式受阻时切换到用户已登录的内置浏览器。确认能读取菜单和终端后继续。
2. 检查线上站点归属、端口、数据库、运行时和空间。判断是首次发布还是升级，确认现有线上数据的处置和回滚点。按 [部署与验证](references/deployment.md) 构建、上传、启动服务和配置站点。
3. 核验线上版本、服务、数据与公网入口。依赖用户输入或第三方服务而未验证的项，明确记录实际限制和剩余操作。
4. 验证后实际写出部署上线文档，默认在项目约定的文档目录保存 Markdown。用户另有格式或位置要求时遵循其要求。使用 [上线文档模板](references/release-report.md)，最终给出文档路径和已验证的站点地址。上线受阻时记录部分结果和下一步，按实际状态标记。

本流程以正常管理登录及用户授权的部署动作开展。每次写入线上配置后核验生效情况。遇到工具明确要求停止、站点归属不清或线上数据库可能被覆盖时，保留已完成结果并说明阻塞。
