# 选择部署方式

- 单文件可执行程序可由 systemd 管理。首次部署需先确定服务用户、目录权限、运行参数和自启方式。升级现有服务可用 [release-binary.sh](../scripts/release-binary.sh)。
- Docker Compose 项目沿用原项目名、卷、环境文件和服务定义。记录前后镜像标签或摘要。先核对持久卷映射，使用目标服务的更新命令，并检查容器健康和业务端点。回滚使用先前镜像和配置。
- Node、Python、Java、PHP 等应用优先沿用项目锁文件、构建命令与当前进程管理方式。将依赖和应用文件放到独立版本目录，保留旧版本，切换服务入口后重启或滚动更新。
- 静态站点发布构建产物，核对站点根目录、路由回退、资源缓存和旧版本恢复路径。数据库步骤根据项目实际需要选择。

## 单二进制升级脚本

Linux 服务器需有 Bash、GNU tar/coreutils、flock 和 systemd。通过已授权的终端以有权写入目标目录和重启服务的用户运行。先确认服务单元实际执行目标文件，验证旧服务正常，并另行评估新程序启动时的数据库迁移。脚本仅适用现有常规可执行文件和 systemd 单元。

使用包含单个文件 app 的 gzip tar 包。先在本地记录 SHA-256。健康检查使用一个可信可执行文件，接收一个发布版本参数，匹配目标版本并确认本地服务健康时返回 0。

```bash
bash release-binary.sh /srv/staging/release.tar.gz "$sha256" \
  /opt/myapp/myapp myapp.service "$version" /srv/staging/check-release
```

脚本校验包、锁定切换、备份旧文件、在同一目录原子替换并重启服务。启动或健康检查失败会恢复旧二进制并尝试重启。此时还需复验旧版本。脚本保留备份，可在公网验收失败时按同样的原子替换顺序手动回滚。数据库备份、迁移和恢复使用数据库对应的流程。
