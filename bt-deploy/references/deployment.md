# 部署与验证

1. **预检。** 读取项目部署配置与运行参数，识别当前版本、构建依赖、数据源和目标架构。在服务器确认操作系统、运行时、磁盘、现有站点配置、端口和服务，识别目标域名是否命中默认站点或已有应用。升级前保留应用、站点配置和数据库的可恢复备份。目标库有现存数据时，先确定合并或迁移方案。
2. **构建与迁移。** 优先沿用项目现有构建流程。服务器有合适运行时可在服务器构建。没有时可按架构本地构建并打包。Go 项目嵌入前端时，从同一提交重建前端，再编译 Linux 二进制。SQLite 使用在线备份或 VACUUM INTO 生成一致快照，在上传前后检查完整性。其他数据库使用适配引擎的备份和恢复工具，并验证迁移后的业务记录或架构。数据库切换前确定写入冻结窗口或增量同步策略，避免遗漏快照后的写入。
3. **上传和启动。** 通过宝塔文件管理器上传到专用非站点目录，校验 SHA-256 后解包。配置独立运行用户、持久化目录和最小文件权限，数据库和运行环境文件放在站点目录以外。沿用项目已有进程管理方案，或用 systemd 管理并设置自启。反代场景优先让应用监听回环地址的空闲端口。若项目不支持配置监听地址，采用适合该环境的隔离方式并记录发布差异。服务端生成所需生产密钥，兼容已有加密数据所需的密钥按项目迁移方案管理。先确认服务活动和本地健康接口，再进行流量切换。
4. **配置站点。** 在宝塔为目标域名创建或更新独立反向代理，指向已验证的应用端口。按应用需要传递 Host、客户端 IP、协议和 WebSocket 头，并核对流式响应的缓冲与超时配置。业务 HTTPS 在范围内时，核对 DNS 与 ACME 验证条件，通过宝塔申请或部署匹配域名的证书。确认公网 HTTPS 可用后，再按站点要求开启 HTTP 跳转。切换后验证 Nginx 配置及现有关键站点。
5. **验收。** 从公网用正常 TLS 验证请求检查首页、至少一项静态资源、项目健康接口和版本。启用 HTTP 跳转时验证状态码及目标。核对服务运行状态和开机策略，以及数据库完整性、关键表记录数量或业务读路径。按需求和可用授权验证登录、接口鉴权、上游调用等关键链路，记录每项实际结果。证书签发中应等待明确结果，失败则查看验证日志并修正具体原因。
6. **收尾。** 记录回滚点和可执行的回滚顺序。上线验收失败时按已授权的范围恢复旧路由或应用版本，并复验。恢复数据库前核对切换后新写入。验证后按保留策略清理或保护带数据库的上传包和临时文件。
