# 连接与回退

按顺序尝试，每次只在得到新证据后重试。以能读取真实登录页、已登录菜单或终端提示符作为可用证据。

1. **直接打开原宝塔 URL。** 在可用的浏览器中访问完整地址，使用原账号走正常登录。没有 Chrome 控制通道时可试内置浏览器。用户已完成登录时，直接定位其实际会话。遇到验证码、证书警告等，按浏览器工具要求由用户完成相关步骤。
2. **做只读网络诊断。** 记录 IP、端口、HTTP 状态及服务端证书的 SAN。对照带斜杠和不带斜杠的已知入口、应用层直连和当前代理，必要时检查系统代理、TUN 路由与物理网卡。只探测用户提供的目标，必要的无凭据证书探测仅用于诊断。一次部署中两条本地路径都返回 Nginx 404，证书覆盖另一业务域名。使用该证书域名连接同一 IP 仍返回 404。端口可连接、证书匹配和宝塔登录页可达分别核验。不要将项目域名证书当作修复面板连接的方法。
3. **尝试现有本地 Chrome。** 列出可用浏览器和标签页，按确切 URL 绑定。窗口标题可见只证明窗口存在。若 Chrome 未接入工具或工具无法核验标签页 URL，按工具要求停止当前路径。用户给出的已登录 /home 地址可帮助定位会话，但复制该地址到新浏览器不会带入登录状态。
4. **复用已登录的内置浏览器。** 这是已验证的回退路径。请用户在 Codex 内置浏览器打开宝塔并登录，然后绑定其实际首页或终端标签页。能读到「网站」「数据库」「文件」「终端」后，优先继续使用同一标签页。若跨轮调用提示浏览器会话不可用，按当前工具文档恢复。曾通过重置浏览器工具的 REPL 并重新绑定已有 /xterm 标签页恢复，重置的是工具会话，避免刷新、关闭用户标签页或清除登录状态。确认「本地服务器」和终端提示符后，先执行只读环境检查。上传通过宝塔「文件」和受支持的文件选择器完成。
5. **备用管理通道。** 用户有 SSH 时使用其明确提供的主机、端口、用户名、认证方式及可核验的主机密钥。不要复用宝塔口令去猜 SSH 凭据。只有宝塔时，可请用户在已登录会话中打开终端，逐步执行检查和部署命令。连用户也遇到 404 时，可让有服务器控制台权限的人核对宝塔实际端口和安全入口，例如在支持该命令的宝塔安装中执行 `sudo bt 14`，只回传入口地址。
